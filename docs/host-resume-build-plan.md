# Host resume build plan

Created 2026-09-20. Status: implemented and code-reviewed; automated check passed. Live activation and native-host acceptance remain unverified.

## Outcome

After ordinary cmux quit/reopen or a supported cmux update, host-restored reader tabs and Dock Folio load their saved URLs and work without a command or refresh. Preserve the document, durable draft/conflict base, and reading position. Queueing from agents continues through the existing CLI and appears in Folio automatically. The host owns tab/layout restoration; Tether never opens historical conversations during recovery.

Hart's audit comments require minimum-version compatibility, never exact version/build/commit pinning. Build and commit may be diagnostic fields only. A socket still requires its normal signed authorization; credentials remain in memory.

This execution targets host quit/reopen with Tether's detached processes surviving, plus reconnection of already-loaded clients when the daemon restarts at its saved origin; a failed top-level navigation before JavaScript loads is not covered. Whole-machine reboot, explicitly stopped Tether, cleared browser storage, and terminated bridge processes require an external startup/authorization mechanism and are separate from ordinary host resume. Do not claim those cases work automatically. Shared cookie and browser recovery improvements apply to Wave/browser; cmux placement is validated first.

## Implementation

1. **Persistent scoped browser access.** Add a renewable 400-day `Max-Age` to reader and Folio cookies, retain HttpOnly/SameSite/path scoping and verifier-only SQLite storage. Renew on authenticated bootstrap/lease/root responses using the presented valid cookie, including preexisting session-only cookies and views reconstructed after daemon restart. Do not expire sessions because of absent leases; existing explicit conversation deletion still revokes access. No new grant can be obtained from a URL or Folio listing. Migration requires an authenticated request before a legacy cookie is discarded; it cannot recover an already-missing cookie. Gate scoped routes on completion of startup/session reconstruction so a valid restored session never receives a false 401 during startup.
2. **Retry actual initialization.** Extract a small tested browser connection coordinator with single-flight execution, retry delay capped at 15 seconds, bounded fetch timeouts, and immediate pageshow/visibility/online retry. Retry bootstrap until editor and recovered draft initialization succeeds. Keep editing/autosave/position writes gated during that initialization; mark it complete before any subsequent network refresh. Remove post-mount refreshAnnotations/lease from the initialization critical path so a late transport failure cannot rerun bootstrap and overwrite a dirty editor. Once initialized, reconnect through lease/revision checks without replacing a dirty editor. Treat 401/403 as an authorization problem rather than endless transport retries. Retain page UI for back-forward cache; clean up only on real teardown. Folio keeps SSE snapshot revalidation and gets bounded, caught retry behavior even without EventSource.
3. **Reading position and drafts.** Avoid overwriting the saved scroll during editor initialization; restore after layout settles. Flush pending position on hiding/leaving. Keep ordered draft writes, catch persistence errors, and retry the current draft after reconnection. Do not add a second, racing beacon draft writer or promise unacknowledged edits survive process death. Preserve conflict detection when disk changed during absence. No full DOM snapshot or expanded editor feature state.
4. **cmux survives host updates.** Remove build equality gates in bridge bootstrap and callbacks. Probe the current compatible host, refresh diagnostic identity, and keep the existing bridge/capability across host downtime. Serialize health/rebinding work so concurrent checks cannot publish inconsistent discovery. Retain the bridge across absent discovery and failed host probes. Accept a replacement daemon after authenticated control identity verification, without a 30-second-only handoff. Never let a failed host probe destroy the retained capability. Do not start a daemon in response to bridge polling, which would undo Quit Tether.
5. **Documentation and activation.** Update README's recovery claims and the audit corrections (socket fingerprint hashes a path; Folio already persists filter/sort preferences); retain precise limits. Register the plan in Folio. After checks and final review, apply the new runtime to the local preview through the existing controlled restart path, if the available host credentials support bridge replacement; otherwise report the exact activation limitation without claiming the live runtime changed.

## Execution result

Implemented persistent and renewable scoped cookies, startup gating for saved sessions, single-flight browser retry, draft-safe editor initialization, scroll restoration/flush, cached-page UI retention, Folio recovery, and minimum-version-compatible cmux bridge reuse/rebinding. The host still owns its tabs; recovery creates no windows. Fixed the favicon response failure with buffered file reading. No commits or host configuration changes.

`bun run check`: **340 passed, 0 failed**, followed by successful TypeScript and web-bundle checks. `git diff --check` passed. The reader test executes the real bundled application in JSDOM and covers transient bootstrap failure, post-mount disconnection, draft/conflict-base preservation, scroll handling, and cached-page UI reuse. Process tests exercise compatible updates, host downtime, unprepared daemon replacement, and rejection of an unrelated listener. Native browser geometry/cookie persistence is not established by JSDOM.

`scripts/check-resume.ts` provides isolated Chromium/WebKit persistent-profile verification. Native browser launch was blocked by macOS Mach-port permissions; escalation did not remove the restriction. The attempted unfocused cmux test terminal was also blocked by socket permissions, so no test workspace was created. The live preview service/bridge has not been replaced and an actual cmux quit/reopen has not been tested. These environment limitations prevent claiming live acceptance; they do not change the implementation scope above.
